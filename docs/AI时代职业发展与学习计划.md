# AI 时代职业发展与学习计划

> 面向：企业开发背景（C#/ASP.NET/前端）、希望往企业级 AI 应用方向突破  
> 投入：每周 16 小时  
> 目标：掌握 RAG/企业知识库与 AI 应用落地，形成可展示项目与简历亮点

---

## 第一部分：分析总结

### 1.1 珠海高新区岗位行情（简要）

| 类型 | 代表企业 | 典型岗位 | 薪资区间 | 与当前背景匹配度 |
|------|----------|----------|----------|------------------|
| 算法/大模型研究 | 金山办公等 | 算法/NLP 工程师 | 20–35k | 偏低（多要求硕士/985） |
| 芯片/嵌入式 AI | 全志等 | AI 软件工程师 | 15–30k | 偏低（C++/Linux/NPU） |
| **AI 应用/工程落地** | 工大智研、各类企业信息化 | 后端/AI 应用、Agent/RAG | 10–20k+ | **高** |

**结论**：对你而言，**企业级 AI 应用 / 用 AI 改造业务** 是更事半功倍的方向。

### 1.2 为什么选「AI 应用 / 企业落地」

- 你的**企业管理系统、业务理解、系统集成**经验可直接复用。
- 市场从「囤算法人才」转向「全业务用 AI」，更缺**能落地的应用型人才**。
- 珠海本地已有「AIGC、AI Agent 优先」的后端岗位，技术栈与 Python + 业务契合。
- **AI 训练师证书**对应提示词设计、数据与效果优化，与开发组合成「开发+懂模型」的复合能力。

### 1.3 建议主攻方向（按优先级）

1. **RAG / 企业知识库**（优先）——把公司文档、制度做成「可问答」的系统。
2. **AI Agent / 流程助手**（延伸）——审批助手、工单分类、内部问答机器人。
3. **内部 Copilot / 提效工具**（延伸）——代码辅助、文档生成、报表解读等。

- **总周期**：约 14 周（约 3.5 个月）。
- **每周**：16 小时，建议拆成「4 天 × 4 小时」或「5 天 × 3 小时 + 1 天 1 小时」。
- **节奏**：前几周偏概念与环境；中间做小项目；后几周做综合项目与复盘。

## 第三部分：知识通俗讲解与举例

### 3.1 大模型 API 调用（像「打电话问专家」）

- **通俗理解**：大模型像一个「什么都能聊的专家」。你通过 API 把问题发过去，它返回一段文字答案。你不需要自己训练模型，只要会发请求、收结果。
- **举例**：  
  - 你发：「请用一句话解释什么是 RAG。」  
  - API 返回：「RAG 就是先查资料再让模型根据资料回答，避免瞎编。」
- **关键点**：请求里通常包含「角色设定 + 用户问题 + 可选的历史对话」，返回里取 `content` 即可。

---

### 3.2 提示词（Prompt）——「怎么问，决定答什么」

- **通俗理解**：同样一个问题，问法不同，答案质量差很多。提示词就是「怎么组织你的问题」：先说明角色、再说明任务、再给格式或例子。
- **举例**：  
  - 差：「报销流程？」→ 可能答得很泛。  
  - 好：「你是公司财务助手。请根据公司制度，用 3 条以内步骤说明员工报销流程，每条一句话。」→ 答案更稳定、可用。
- **常见结构**：角色（你是谁）+ 任务（要干什么）+ 格式（分点/表格/字数）+ 示例（可选）。

---

### 3.3 向量与相似度（「意思相近」用数字表示）

- **通俗理解**：计算机不懂文字，但可以把一句话变成一长串数字（向量）。意思相近的句子，对应的向量会「离得近」；意思远的就「离得远」。这样就能用「距离」来检索「和问题最相关的段落」。
- **举例**：  
  - 「请假要提前申请」→ 向量 A。  
  - 「员工请假流程」→ 向量 B。  
  - 「今天天气不错」→ 向量 C。  
  A 和 B 的距离小（相关），A 和 C 的距离大（不相关）。RAG 里就是用「用户问题」的向量去找距离最小的几段文档。

---

### 3.4 RAG（检索增强生成）——「先查资料再回答」

- **通俗理解**：大模型会「瞎编」。RAG 的做法是：**先**用你的问题去知识库（文档切块+向量）里查最相关的几段，**再**把这几段和问题一起交给模型，让它「只根据这些资料回答」。这样既减少瞎编，又能用上公司内部文档。
- **举例**：  
  - 用户问：「年假有几天？」  
  - 系统先检索到制度里「年假 5 天」那段话。  
  - 再让模型读这段话并生成：「根据公司制度，年假为 5 天。」

---

### 3.5 文档切块（Chunking）——「把长文档拆成小段」

- **通俗理解**：一整本 PDF 不能一次性塞给模型（太长且贵）。所以要按「块」来切：每块几百字，块与块可以有一点重叠，避免一句话被截断。
- **举例**：一段 1000 字的制度，按 300 字一块、重叠 50 字切，得到 3～4 块。检索时是以「块」为单位，找到最相关的几块再拼给模型。

---

### 3.6 向量库——「存向量、按相似度查」

- **通俗理解**：把很多文档块的向量存进专门的数据里，支持「给我和这个向量最像的 K 条」。这就是向量数据库。常见的有 Chroma、Milvus、Qdrant 等。
- **举例**：你有一万条制度片段，都转成向量存进 Chroma。用户问「加班怎么算」，把问题转成向量，在 Chroma 里查 Top-5，就得到 5 段最相关的制度原文。

---

### 3.7 Agent——「会自己选工具、多步执行」

- **通俗理解**：普通调用是「问一次答一次」。Agent 是：模型先「想一步」，决定要调用哪个工具（如查知识库、查天气、查数据库），执行完再把结果给它，它再决定下一步，直到给出最终答案。
- **举例**：用户问「珠海明天天气怎么样，适不适合户外团建？」  
  Agent 可能先调「天气 API」，再调「知识库：团建注意事项」，最后综合两边的结果生成回答。

---

### 3.8 LangChain——「拼积木的框架」

- **通俗理解**：RAG 里有很多环节：读文档、切块、向量化、存库、检索、拼上下文、调模型。LangChain 把这些都做成现成组件，你主要做「选哪个组件、怎么连」，减少自己造轮子。
- **举例**：用 LangChain 的 `PyPDFLoader` 读 PDF，`RecursiveCharacterTextSplitter` 切块，`Chroma` 存向量，`RetrievalQA` 把「检索+生成」绑在一起，几十行代码就能跑通一个简单 RAG。

## 第四部分：小项目列表（供学习与简历）

### 项目 1：单 PDF 知识库问答（第 6 周）

- **目标**：从零实现一个最小 RAG：一个 PDF → 切块 → 向量化 → 存库 → 提问时检索并生成回答。
- **技术点**：PyPDF 或 pdfplumber、切块、嵌入 API、Chroma（或内存向量列表）、大模型 API、简单拼接逻辑。
- **产出**：本地脚本，输入 PDF 路径和问题，输出答案；可加 5 个固定问答做自测。
- **参考目录**：`projects/01-single-pdf-rag/`（见下文项目结构）。

---

### 项目 2：多文档知识库问答（第 9 周）

- **目标**：支持多个 PDF/TXT；为每个文档打标签（如部门、类型）；提问时可选择「只在某类文档里查」。
- **技术点**：多文件加载、元数据/标签、向量库按元数据过滤、LangChain 可选。
- **产出**：命令行或简单 Web 页：上传/指定目录 → 建索引 → 按标签选范围 → 提问。
- **参考目录**：`projects/02-multi-doc-rag/`。

---

### 项目 3：企业场景小应用（第 12 周）

- **目标**：选一个真实场景（如：公司制度问答 / 项目 Wiki 问答 / 客服 FAQ），从准备数据到可演示的 Demo。
- **技术点**：数据清洗、切块与检索调优、提示词设计、简单 Web（FastAPI + 前端或 Streamlit）、效果自测（用训练师思路写 10 个问答对）。
- **产出**：可演示的页面 + README + 简短效果说明；可录屏放简历。
- **参考目录**：`projects/03-enterprise-rag-demo/`。

---

### 项目 4：带工具调用的 Agent Demo（第 11 周）

- **目标**：用 LangChain Agent 实现「查知识库 + 调 1 个外部工具（如天气/计算器）」。
- **技术点**：LangChain Agent、自定义 Tool、把 RAG 封装成一个 Tool。
- **产出**：一个脚本或简单对话界面：用户问混合问题，Agent 自动选「先查库再答」或「先调工具再答」。
- **参考目录**：`projects/04-agent-with-tools/`。
